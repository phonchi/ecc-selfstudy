§5.1

把 $k$ 個 $P$ 加起來，但不能真的加 $k$ 次

動機

ECC 的公開金鑰是 $Q=kG$，ECDH 的共同秘密是 $a(bG)$：所有協定的核心都是純量乘法 $kP$。$k$ 是 256 位元左右的整數，大約 $2^{256}$，一個一個加顯然不可能。我們需要只用 $O(\log k)$ 次點運算的方法，而且要算清楚：一次 $kP$ 到底要多少次 $\mathbb F_p$ 乘法？這個數字決定了後面四章為什麼值得花力氣。

§5.2

double-and-add

這和第 1 章計算 $a^{p-2}$ 的平方-乘是同一個演算法，只是群運算寫成加法：把 $k$ 寫成二進位，由最高位往下讀，每讀一位先把目前的點倍點，讀到 1 再加上 $P$。正確性來自 Horner 形式：

$$k=(\cdots((k_{\ell-1})\,2+k_{\ell-2})\,2+\cdots)\,2+k_0 .$$

讀完前 $j$ 位時，手上的點恰好是「這 $j$ 位所代表的整數」乘上 $P$。$\ell$ 位元的 $k$ 需要 $\ell-1$ 次倍點，以及（$k$ 中 1 的個數減 1）次加點。隨機的 $k$ 平均約一半位元是 1，所以大約 $\ell/2$ 次加點。

三種純量乘法
def scalar_mult(k, P, a, p):
    """由左而右的 double-and-add：每讀一位先倍點，位元為 1 再加 P。"""
    R = O
    for bit in bin(k)[2:]:
        R = ec_add(R, R, a, p)          # 倍點
        if bit == "1":
            R = ec_add(R, P, a, p)      # 加點
    return R


def naf(k):
    """非相鄰形式：數字取 -1, 0, 1，且沒有兩個相鄰的非零位。由低位到高位。"""
    digits = []
    while k > 0:
        if k % 2 == 1:
            d = 2 - (k % 4)             # k = 1 (mod 4) 取 1，k = 3 (mod 4) 取 -1
            k -= d
        else:
            d = 0
        digits.append(d)
        k //= 2
    return digits


def scalar_mult_naf(k, P, a, p):
    R = O
    minusP = ec_neg(P, p)
    for d in reversed(naf(k)):
        R = ec_add(R, R, a, p)
        if d == 1:
            R = ec_add(R, P, a, p)
        elif d == -1:
            R = ec_add(R, minusP, a, p)
    return R


def ladder(k, P, a, p):
    """Montgomery ladder：每一位都做一次加點與一次倍點，並保持 R1 - R0 = P。"""
    R0, R1 = O, P
    for bit in bin(k)[2:]:
        if bit == "0":
            R0, R1 = ec_add(R0, R0, a, p), ec_add(R0, R1, a, p)
        else:
            R0, R1 = ec_add(R0, R1, a, p), ec_add(R1, R1, a, p)
    return R0
§5.3

NAF：減法是免費的

橢圓曲線上取負號幾乎不花成本：$-(x,y)=(x,-y)$。所以「減 $P$」和「加 $P$」一樣便宜，可以允許 $k$ 的數字是 $-1,0,1$。這樣的表示法很多，其中非相鄰形式（non-adjacent form，NAF）要求任兩個相鄰的數字不同時為非零。每個正整數恰有一個 NAF，而且它的非零數字最少。

小例

$7=(111)_2$ 要加兩次；它的 NAF 是 $(1\,0\,0\,\bar1)=8-1$，只要減一次。$45=(101101)_2$ 有 4 個 1，NAF 是 $(1\,0\,\bar1\,0\,\bar1\,0\,1)=64-16-4+1$，非零數字也是 4 個，但長度多一位。

平均而言，NAF 的非零數字約佔 $1/3$（隨機 256 位元的 $k$ 平均約 86 個，二進位則約 128 個），所以加點次數從約 $\ell/2$ 降到約 $\ell/3$。更進一步的 wNAF 預先算好 $3P,5P,\dots$，非零數字更稀疏（HMV 演算法 3.36）。

§5.4

一次 $kP$ 的成本帳

用第 4 章的 Jacobian 公式（$a=-3$ 倍點 3M + 5S，混合加點 7M + 4S，最後一次反元素約 100M），假設 $\mathbf S=0.8\,\mathbf M$，256 位元的 $k$：

方法倍點加點約略總成本
double-and-add255約 128約 3 200 M
NAF255約 85約 2 800 M
Montgomery ladder256256（一般加點）約 5 700 M

結論是：一次純量乘法 ≈ 三千到六千次 $\mathbb F_p$ 乘法。一次 ECDH 每一方要做一兩次純量乘法。把一次 $\mathbb F_p$ 乘法加快 20%，整個協定大約就快 20%。這就是成本鏈的下一層：第 6 章算整數乘積，第 7 到 9 章做化簡。

§5.5

旁通道與 Montgomery 階梯

double-and-add 有一個實際的弱點：讀到 0 只做倍點，讀到 1 多做一次加點。攻擊者若能量測晶片的耗電或時間（旁通道，side channel），就能從「倍點、倍點加點、倍點……」的節奏直接讀出 $k$ 的位元。這叫簡單功率分析（simple power analysis，SPA）。下面的互動元件會畫出這條「節奏」。

Montgomery 階梯（Montgomery ladder）讓每一位做的事都一樣：同時維護兩個點 $R_0,R_1$，並保持

$$R_1-R_0=P .$$

讀到 0 時令 $(R_0,R_1)\leftarrow(2R_0,\ R_0+R_1)$，讀到 1 時令 $(R_0,R_1)\leftarrow(R_0+R_1,\ 2R_1)$。兩種情形都是一次加點加一次倍點，而且不變量保持成立；最後 $R_0=kP$。差別只在「哪一個被倍點」，實作上用一個與資料無關的條件交換（cswap）處理。

規則的排程還不夠

操作順序固定只是第一步。常數時間的實作還要求：不能有依賴秘密的分支或記憶體位址（cswap 要用遮罩做），底層的 $\mathbb F_p$ 運算本身也必須是常數時間（第 8、9 章最後的條件減法就是一個例子）。本站的 JavaScript BigInt 示範不是常數時間，只用來說明演算法。

階梯和第 9 章的 Montgomery 乘法、以及 Montgomery 形式的曲線是三件不同的事；它在 $y^2=x^3+ax+b$ 上同樣可以用（HECC §13.2.3），在 Montgomery 曲線上則可以只用 $x$ 座標，特別省（RFC 7748 §5）。
