第 0 章 · Why Elliptic Curves

為什麼是橢圓曲線

同樣的安全強度，金鑰短很多；而一切成本最後都落在 mod p 的乘法

成本鏈協定 ECDH→純量乘法 kP→加點／倍點→模乘 mod p→字組乘法

0.1在公開的通道上約定一個祕密

動機

Alice 和 Bob 從沒見過面，只能透過一條所有人都聽得到的通道說話。他們想約定一把只有兩人知道的金鑰（key），之後用它加密大量資料。對稱式加密（例如 AES）本身很快也很安全，難處在於「第一把金鑰怎麼來」。

這就是公開金鑰密碼（public-key cryptography）要解的問題。它需要一種單向運算：正著算很容易，倒推回去卻難到不可行。本章說明：在一個循環群裡，「次方」就是這樣的運算；而橢圓曲線上的點群，是目前已知同樣安全強度下金鑰最短的選擇。

整個網站圍繞一個問題：這個單向運算在電腦上到底花多少力氣。答案一層一層往下拆，最後落在「兩個幾百位元的整數相乘再取模 $p$」。本章最後一節把這條成本鏈畫出來，作為全站的地圖。

0.2離散對數：容易的方向與困難的方向

設 $G$ 是一個循環群，生成元為 $g$，階為 $n$。給定整數 $k$，算

$$h = g^k$$

很容易：平方-乘（square-and-multiply）（square-and-multiply）依 $k$ 的二進位逐位處理，每一位做一次平方，遇到 1 再乘一次 $g$。$k$ 有 $\ell$ 個位元時，最多 $2\ell$ 次群運算；$k$ 有 256 位元，就是幾百次，而不是 $2^{256}$ 次。

反方向，給定 $g$ 與 $h$ 求 $k$，叫做離散對數問題（discrete logarithm problem，DLP）。若群的階 $n$ 是大質數，而且群元素沒有可以利用的特殊結構，已知最好的通用演算法（Pollard rho、baby-step giant-step）大約要 $\sqrt n$ 次群運算。（$n$ 若是合數，問題可以拆到較小的子群上解，第 3 章會說明。）$n\approx2^{256}$ 時就是約 $2^{128}$ 次，遠超出任何可行的計算量。

同一個問題，不同的群

難度不只取決於 $n$ 的大小，還取決於群是怎麼表示的。

  • $\mathbb F_p^{*}$（乘法群）：元素是整數，可以談「小質因數」。指標演算法（index calculus）利用這一點：先求出一組小質數的離散對數，再把目標元素分解到這組小質數上。它的變形（數域篩法）讓 $\mathbb F_p^{*}$ 上的 DLP 只需次指數（subexponential）時間，所以 $p$ 必須取到兩三千位元以上，而且安全需求每提高一級，$p$ 要長得更快。
  • 橢圓曲線的點群 $E(\mathbb F_p)$：群運算寫成 $P+Q$，「一個點的 $k$ 倍」記作 $kP$。點沒有「分解成小點」的自然方法，對於挑選得當的曲線，至今沒有已知的指標演算法類比。最好的攻擊仍是通用的 $\sqrt n$ 級演算法（第 3 章）。

對應地，橢圓曲線上的單向運算是純量乘法（scalar multiplication）

$$k \ \longmapsto\ Q = kG ,$$

反方向的「已知 $G,Q$ 求 $k$」稱為 ECDLP。平方-乘在這裡變成 double-and-add：平方換成倍點 $2R$，乘以 $g$ 換成加上 $G$。

注意

「沒有已知的次指數攻擊」是經驗事實，不是定理。有些特殊曲線確實較弱（例如超奇異曲線可以用配對轉到有限體上，異常曲線可以在多項式時間內解）；標準曲線的參數就是為了避開這些情形而選的。第 3 章會列出要避開的條件。另外，上面所有的難度估計都只針對古典電腦；大型量子電腦上的 Shor 演算法對 $\mathbb F_p^{*}$ 與橢圓曲線都能在多項式時間內解出離散對數。

0.3同樣的安全強度，金鑰差多少

「安全強度 $s$ 位元」的意思是：已知最好的攻擊大約要 $2^{s}$ 次運算。NIST SP 800-57 Part 1 Rev. 5 的 Table 2 把不同演算法族群的參數大小對到同一把尺上：

安全強度（位元）RSA 模數（IFC）有限體 DH／DSA（FFC）的 $p$橢圓曲線（ECC）的 $n$
11220482048224–255
12830723072256–383
19276807680384–511
2561536015360512 以上

資料來源：NIST SP 800-57 Part 1 Rev. 5，§5.6.1.1 Table 2（只考慮古典攻擊）。FFC 一欄另有子群階 $N$ 的大小（224／256／384／512 位元），這裡省略。

ECC 一欄是基點 $G$ 的階 $n$ 的位元數（餘因子 $h=1$ 的曲線，例如 P-256，$n$ 就等於整個群的點數），大約是安全強度的兩倍，這正是 $\sqrt n$ 攻擊的直接結果。RSA 與 FFC 一欄則因為次指數攻擊而增長得快得多：從 112 位元到 256 位元的強度，ECC 的大小約變為 2.3 倍（224 到 512），RSA 卻變為 7.5 倍（2048 到 15360）。

所以常聽到的說法「P-256 約等於 RSA-3072」就是表中 128 位元那一列：P-256 的群階有 256 位元，落在 256–383 的範圍內。金鑰短，意味著傳輸的公鑰短、儲存小，而且同等安全強度下，點運算的模數也比 RSA 的模數短得多。

0.4ECDH：兩次純量乘法約出一把金鑰

橢圓曲線 Diffie–Hellman（ECDH）直接把上面的單向運算拿來用。雙方先約定公開的網域參數（domain parameters）：曲線 $E$、底體 $\mathbb F_p$、一個階為質數 $n$ 的點 $G$。標準曲線（例如 P-256）把這些參數全部固定公布。

AliceBob
1. 選私鑰隨機 $a\in[1,n-1]$隨機 $b\in[1,n-1]$
2. 算公鑰$A=aG$$B=bG$
3. 交換把 $A$ 送給 Bob把 $B$ 送給 Alice
4. 算共享點$aB$$bA$

因為群是交換的，

$$aB = a(bG) = (ab)G = b(aG) = bA ,$$

兩人得到同一個點 $S=(ab)G$。竊聽者看得到 $G,A,B$，要算 $S$ 就得解出 $a$ 或 $b$（或者解所謂的計算 Diffie–Hellman 問題，目前沒有比解 ECDLP 更好的方法）。

實務上不直接拿 $S$ 當金鑰，而是取它的 $x$ 座標，送進金鑰衍生函數（key derivation function，KDF）產生固定長度、分布均勻的對稱金鑰。RFC 7748 §6 的 X25519 也是同樣的流程，只是用另一種曲線形式和只算 $x$（在那裡叫 $u$）座標的 Montgomery ladder（第 5 章）。

小例：曲線 $y^2=x^3-3x+6$，$\mathbb F_{97}$，共 107 個點

107 是質數，所以除了 $\mathcal O$ 以外每一點都是生成元。取 $G=(0,43)$、$a=23$、$b=61$：

$$A=23G=(78,73),\qquad B=61G=(35,22),$$ $$23B = 61A = (72,49) = 12\,G ,$$

其中 $12 \equiv 23\cdot61 \pmod{107}$。共享的 $x$ 座標是 $72$。（這些值由 python/ecc_ref.py 的 scalar_mult 算出，下一節的互動元件用同樣的預設值。）

ECDH 沒有做到的事

  • 身分認證。裸的 ECDH 不知道對方是誰。中間人（man-in-the-middle）可以分別和 Alice、Bob 各做一次 ECDH，再在中間轉送並讀取所有訊息。實際協定（例如 TLS）會用數位簽章（ECDSA、EdDSA）或憑證把公鑰綁到身分上；簽章不在本站範圍內。
  • 公鑰驗證。收到的 $B$ 必須先檢查：不是 $\mathcal O$、座標在 $[0,p)$ 內、確實滿足曲線方程式（餘因子不為 1 時還要檢查階）。否則攻擊者可以送一個不在曲線上的點，讓對方的計算落在另一條群階很小的曲線上，從回應洩漏私鑰的片段（invalid-curve attack）。HMV §4.3 有完整的驗證步驟。

從計算的角度，ECDH 每一方只做兩次純量乘法：$aG$（基點固定，可以預先算表加速）與 $aB$（基點每次不同）。如果私鑰長期重複使用，$aG$ 只要算一次，每次交換就只剩一次。下面的程式就是雙方唯一需要的運算。

Python 參考實作（選讀）：純量乘法：ECDH 雙方唯一需要的運算
def scalar_mult(k, P, a, p):
    """由左而右的 double-and-add：每讀一位先倍點，位元為 1 再加 P。"""
    R = O
    for bit in bin(k)[2:]:
        R = ec_add(R, R, a, p)          # 倍點
        if bit == "1":
            R = ec_add(R, P, a, p)      # 加點
    return R


def naf(k):
    """非相鄰形式：數字取 -1, 0, 1，且沒有兩個相鄰的非零位。由低位到高位。"""
    digits = []
    while k > 0:
        if k % 2 == 1:
            d = 2 - (k % 4)             # k = 1 (mod 4) 取 1，k = 3 (mod 4) 取 -1
            k -= d
        else:
            d = 0
        digits.append(d)
        k //= 2
    return digits


def scalar_mult_naf(k, P, a, p):
    R = O
    minusP = ec_neg(P, p)
    for d in reversed(naf(k)):
        R = ec_add(R, R, a, p)
        if d == 1:
            R = ec_add(R, P, a, p)
        elif d == -1:
            R = ec_add(R, minusP, a, p)
    return R


def ladder(k, P, a, p, bits=0):
    """Montgomery ladder：每一位都做一次加點與一次倍點，並保持 R1 - R0 = P。
    bits 是公開的固定長度（例如 n 的位元數），k 前面補 0，迴圈次數就不洩漏 k 的長度。
    這裡的 if 與 Python 整數運算都不是常數時間，只用來說明演算法。"""
    R0, R1 = O, P
    for bit in bin(k)[2:].zfill(bits):
        if bit == "0":
            R0, R1 = ec_add(R0, R0, a, p), ec_add(R0, R1, a, p)
        else:
            R0, R1 = ec_add(R0, R1, a, p), ec_add(R1, R1, a, p)
    return R0

0.6成本鏈與本站地圖

一次 ECDH 的成本，可以沿著下面這條鏈一層一層往下拆。每一層都由下一層的運算組成，也剛好對應本站的章節：

  1. 協定ECDH：每一方一到兩次純量乘法。本章
  2. 純量乘法$kP$：$k$ 有幾百位元，double-and-add 要做幾百次倍點與加點；換算下來是幾千次 $\mathbb F_p$ 乘法。第 5 章；為什麼難倒推見 第 3 章
  3. 點運算加點／倍點：仿射公式每步要一次求反元素；換成 Jacobian 座標後只剩十來次乘法。第 2 章、第 4 章
  4. 模乘$xy \bmod p$：先得到兩倍長的乘積，再化簡回 $[0,p)$。特殊形狀的 $p$ 用折疊，一般的 $p$ 用 Barrett 或 Montgomery。第 1 章、第 7 章、第 8 章、第 9 章
  5. 字組字組乘法：256 位元的數切成 4 個 64 位元字組，逐格相乘並處理進位。第 6 章

讀法有兩種。由上往下是「為什麼」：協定需要 $kP$，$kP$ 需要點運算，點運算需要模乘。由下往上是「花多少」：字組乘法的次數乘上去，就得到一次 ECDH 的總成本。每章頁首的那條膠囊列就是這條鏈，亮起的那一格是該章所在的層。

本站的章節順序是先打數學基礎（第 1–3 章：有限體、群律、群結構與 ECDLP），再從曲線走到運算成本（第 4–5 章），然後花四章處理最底層、也最常被執行的模乘法（第 6–9 章），最後在 第 10 章把各層的選擇放在一起比較。
