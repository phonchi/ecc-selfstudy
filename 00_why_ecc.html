第 0 章 · Why Elliptic Curves

為什麼是橢圓曲線

同樣的安全強度，金鑰短很多；而一切成本最後都落在 mod p 的乘法

成本鏈協定 ECDH→純量乘法 kP→加點／倍點→模乘 mod p→字組乘法

0.1在公開的通道上約定一個祕密

動機

Alice 和 Bob 從沒見過面，只能透過一條所有人都聽得到的通道說話。他們想約定一把只有兩人知道的金鑰（key），之後用它加密大量資料。對稱式加密（例如 AES）本身很快也很安全，難處在於「第一把金鑰怎麼來」。

這就是公開金鑰密碼（public-key cryptography）要解的問題。它需要一種單向運算：正著算很容易，倒推回去卻難到不可行。本章說明：在一個群裡，「重複做同一個運算」就是這樣的單向運算；而橢圓曲線（正式定義見 定義 2.1）上的點所成的群，是目前已知在同樣的安全要求下金鑰最短的選擇。

本章是序章，只用白話描述，正式的定義放在第 1、2 章。下面先列出本章會用到的詞，每個都附上正式定義的位置。

注意 0.1本章用到的詞（白話版）
  • 群：一個集合加上一種運算，有單位元、每個元素有反元素、滿足結合律。正式定義見 定義 1.4。
  • 元素的階、循環群、生成元：$g$ 重複運算幾次會回到單位元，就是 $g$ 的階；若某個 $g$ 重複運算能走遍整個群，這個群叫循環群，$g$ 叫生成元。見 定義 1.6。
  • $\mathbb F_p$：$p$ 是質數，整數模 $p$ 的加減乘除都能精確地做，這樣的數系叫質數體。見 定義 1.11。
  • 橢圓曲線的點群 $E(\mathbb F_p)$：滿足 $y^2=x^3+ax+b$ 的點 $(x,y)$（$x,y\in\mathbb F_p$），再加上一個「無窮遠點」$\mathcal O$，可以定義「點加點」，成為一個群，$\mathcal O$ 是單位元。見 定義 2.1 與 定理 2.6。
  • 純量乘法 $kP$：點 $P$ 自己加 $k$ 次。群用加法寫法時，$kP$ 就是乘法寫法裡的 $g^k$（注意 1.5）。

整個網站圍繞一個問題：這個單向運算在電腦上到底花多少力氣。答案一層一層往下拆，最後落在「兩個幾百位元的整數相乘再取模 $p$」。本章最後一節把這條成本鏈畫出來，作為全站的地圖。

0.2離散對數：容易的方向與困難的方向

公開金鑰需要一個「正著算容易、反著算困難」的運算。在循環群裡，次方就是這樣的運算。

設 $G$ 是一個階為 $n$ 的循環群，生成元為 $g$（定義 1.4、定義 1.6）。給定整數 $k$，算 $y=g^k$ 很容易：平方-乘（演算法 1.16）依 $k$ 的二進位逐位處理，每一位做一次平方，遇到 1 再乘一次 $g$。$k$ 有 $\ell$ 個位元時，最多 $2\ell$ 次群運算；$k$ 有 256 位元，就是幾百次，而不是 $2^{256}$ 次。

定義 0.2離散對數問題、DLPHAC Def. 3.52

設 $G$ 是循環群、$g$ 是生成元。給定 $y\in G$，求整數 $k$（$0\le k<n$）使 $g^k=y$，稱為離散對數問題（discrete logarithm problem，DLP），$k$ 記作 $\log_g y$。

若群的階 $n$（定義 1.4）是大質數，而且群的元素沒有可以利用的特殊結構，已知最好的通用演算法（只用群運算、不看元素怎麼表示的演算法，例如 Pollard rho，第 3 章）大約要 $\sqrt n$ 次群運算。（$n$ 若是合數，問題可以拆到較小的子群上解；子群見 定義 1.6，拆解的方法在第 3 章。）$n\approx2^{256}$ 時就是約 $2^{128}$ 次，遠超出任何可行的計算量。

同一個問題，不同的群

難度不只取決於 $n$ 的大小，還取決於群的元素是怎麼表示的。

  • $\mathbb F_p^*$（定義 1.11）：元素是整數，可以談「分解成小質數」。指標演算法（index calculus）利用這一點：先求出一組小質數的離散對數，再把目標元素分解到這組小質數上。它的改良（數域篩法）讓 $\mathbb F_p^*$ 上的 DLP 只需次指數時間（比 $p$ 的任何多項式都慢、但比 $\sqrt p$ 快得多），所以 $p$ 必須取到兩三千位元以上。
  • 橢圓曲線的點群 $E(\mathbb F_p)$：點沒有「分解成小點」的自然方法。對於挑選得當的曲線，至今沒有已知的指標演算法類比，最好的攻擊仍是通用的 $\sqrt n$ 級演算法（第 3 章）。
定義 0.3ECDLP、基點HMV §4.1

設 $E$ 是 $\mathbb F_p$ 上的橢圓曲線，$G\in E(\mathbb F_p)$ 是一個階為 $n$ 的點，稱為基點（base point）。給定 $Q\in\langle G\rangle$，求 $k\in[0,n-1]$ 使 $Q=kG$，稱為橢圓曲線離散對數問題（ECDLP）。

對應地，橢圓曲線上的單向運算是純量乘法 $k\mapsto kG$。平方-乘在這裡變成 double-and-add：平方換成「點自己加自己」（倍點），乘以 $g$ 換成加上 $G$（第 5 章）。

注意 0.4「困難」是經驗事實

「沒有已知的次指數攻擊」是經驗事實，不是定理。有些特殊曲線確實較弱，標準曲線的參數就是為了避開這些情形而選的（第 3 章列出條件）。另外，上面所有的難度估計都只針對古典電腦；大型量子電腦上的 Shor 演算法對 $\mathbb F_p^*$ 與橢圓曲線都能在多項式時間內解出離散對數。

0.3同樣的安全強度，金鑰差多少

既然 $\mathbb F_p^*$ 有次指數攻擊、橢圓曲線沒有，要達到同樣的安全，兩者需要的參數大小就差很多。這是選擇橢圓曲線最直接的理由。

定義 0.5安全強度SP 800-57 §5.6.1

一個演算法的安全強度為 $s$ 位元，意思是已知最好的攻擊大約需要 $2^s$ 次運算。

NIST SP 800-57 Part 1 Rev. 5 的 Table 2 把不同演算法族群的參數大小對到同一把尺上：

資料來源：NIST SP 800-57 Part 1 Rev. 5，§5.6.1.1 Table 2（只考慮古典攻擊）。RSA 是以大數分解為基礎的公開金鑰系統，這裡只用來比較長度；FFC 一欄另有第二個參數，這裡省略。

ECC 一欄是基點的階 $n$ 的位元數，大約是安全強度的兩倍，這正是 $\sqrt n$ 攻擊的直接結果。RSA 與 FFC 一欄則因為次指數攻擊而增長得快得多：從 112 位元到 256 位元的強度，ECC 的大小約變為 2.3 倍（224 到 512），RSA 卻變為 7.5 倍（2048 到 15360）。常聽到的「P-256 約等於 RSA-3072」就是表中 128 位元那一列（P-256 是 NIST 標準曲線，它的 $n$ 有 256 位元，第 3 章列出完整參數）。

0.4ECDH：兩次純量乘法約出一把金鑰

有了單向運算，就能回答本章開頭的問題：兩個人怎麼在公開的通道上約出一個祕密。

定義 0.6網域參數、ECDH、私鑰、公鑰HMV §4.3, §4.6

雙方先約定公開的網域參數（domain parameters）：質數 $p$、曲線 $E:y^2=x^3+ax+b$、基點 $G$ 與它的質數階 $n$。橢圓曲線 Diffie–Hellman（ECDH）的步驟：

  1. Alice 隨機選私鑰 $d_A\in[1,n-1]$，算公鑰 $Q_A=d_AG$；Bob 同樣選 $d_B$，算 $Q_B=d_BG$。
  2. 交換公鑰。
  3. Alice 算 $d_AQ_B$，Bob 算 $d_BQ_A$。

因為 $d_A(d_BG)=(d_Ad_B)G=d_B(d_AG)$（純量乘法的性質，第 5 章），兩人得到同一個點 $S=(d_Ad_B)G$。竊聽者看得到 $G,Q_A,Q_B$；要算 $S$，目前沒有比解 ECDLP 更好的方法。

實務上不直接拿 $S$ 當金鑰，而是取它的 $x$ 座標，送進金鑰衍生函數（key derivation function，KDF：把一個數轉成固定長度、分布均勻的對稱金鑰的函數）。

小例：曲線 $y^2=x^3-3x+6$，$\mathbb F_{97}$，共 107 個點

107 是質數，由 Lagrange 定理（定理 1.7），除了無窮遠點 $\mathcal O$（定義 2.2）以外每一點的階都是 107，都是生成元（定義 1.6）。取 $G=(0,43)$、$d_A=23$、$d_B=61$：

$$Q_A=23G=(78,73),\qquad Q_B=61G=(35,22),$$ $$23\,Q_B = 61\,Q_A = (72,49) = 12\,G ,$$

其中 $12 \equiv 23\cdot61 \pmod{107}$。共享的 $x$ 座標是 $72$。

注意 0.7另一個用途：ECDSA 簽章，以及模 n 的運算

ECDH 本身不能確認對方的身分：中間人（man-in-the-middle）可以分別和 Alice、Bob 各做一次 ECDH，再在中間轉送訊息。實際協定會用數位簽章把公鑰綁到身分上，最常見的是 ECDSA（Elliptic Curve Digital Signature Algorithm，HMV §4.4.1）。本站不講簽章的細節，只需要知道一件事：ECDSA 除了純量乘法，還要在模基點階 $n$ 下做整數運算（例如算 $k^{-1}\bmod n$ 與幾次模 $n$ 的乘法）。$n$ 是由曲線決定的大質數，通常沒有特殊形狀，所以第 8、9 章的一般化簡方法也用得上。

注意 0.8公鑰驗證

收到的 $Q_B$ 必須先檢查：不是 $\mathcal O$、座標在 $[0,p)$ 內、確實滿足曲線方程式。否則攻擊者可以送一個不在曲線上的點，讓對方的計算落在另一條群很小的曲線上，從回應洩漏私鑰的片段（invalid-curve attack，HMV §4.3）。

Python 參考實作（選讀）：純量乘法：ECDH 雙方唯一需要的運算
def scalar_mult(k, P, a, p):
    """由左而右的 double-and-add：每讀一位先倍點，位元為 1 再加 P。"""
    R = O
    for bit in bin(k)[2:]:
        R = ec_add(R, R, a, p)          # 倍點
        if bit == "1":
            R = ec_add(R, P, a, p)      # 加點
    return R


def naf(k):
    """非相鄰形式：數字取 -1, 0, 1，且沒有兩個相鄰的非零位。由低位到高位。"""
    digits = []
    while k > 0:
        if k % 2 == 1:
            d = 2 - (k % 4)             # k = 1 (mod 4) 取 1，k = 3 (mod 4) 取 -1
            k -= d
        else:
            d = 0
        digits.append(d)
        k //= 2
    return digits


def scalar_mult_naf(k, P, a, p):
    R = O
    minusP = ec_neg(P, p)
    for d in reversed(naf(k)):
        R = ec_add(R, R, a, p)
        if d == 1:
            R = ec_add(R, P, a, p)
        elif d == -1:
            R = ec_add(R, minusP, a, p)
    return R


def ladder(k, P, a, p, bits=0):
    """Montgomery ladder：每一位都做一次加點與一次倍點，並保持 R1 - R0 = P。
    bits 是公開的固定長度（例如 n 的位元數），k 前面補 0，迴圈次數就不洩漏 k 的長度。
    這裡的 if 與 Python 整數運算都不是常數時間，只用來說明演算法。"""
    R0, R1 = O, P
    for bit in bin(k)[2:].zfill(bits):
        if bit == "0":
            R0, R1 = ec_add(R0, R0, a, p), ec_add(R0, R1, a, p)
        else:
            R0, R1 = ec_add(R0, R1, a, p), ec_add(R1, R1, a, p)
    return R0

0.6成本鏈與本站地圖

本站要回答的是：一次 ECDH 到底花多少力氣。這個成本可以沿著下面這條鏈一層一層往下拆，每一層都由下一層的運算組成，也剛好對應本站的章節：

  1. 協定ECDH：每一方一到兩次純量乘法。本章
  2. 純量乘法$kP$：$k$ 有幾百位元，要做幾百次「點加點」；換算下來是幾千次 $\mathbb F_p$ 乘法。第 5 章；為什麼難以倒推見 第 3 章
  3. 點運算加點與倍點：每一次都是十幾次 $\mathbb F_p$ 的加減乘除；怎麼避開昂貴的除法是第 4 章的主題。第 2 章、第 4 章
  4. 模乘$xy \bmod p$：先得到兩倍長的整數乘積，再化簡回 $[0,p)$。第 1 章、第 7–9 章
  5. 字組乘法大整數相乘：電腦一次只能乘 64 位元，256 位元的數要拆成好幾段來乘。第 6 章

讀法有兩種。由上往下是「為什麼」：協定需要 $kP$，$kP$ 需要點運算，點運算需要模乘。由下往上是「花多少」：字組乘法的次數乘上去，就得到一次 ECDH 的總成本。每章頁首的那條膠囊列就是這條鏈，亮起的那一格是該章所在的層。

章節順序：第一部（第 1–3 章）打數學基礎，第二部（第 4–5 章）從曲線走到運算成本，第三部（第 6–9 章）處理最底層、也最常被執行的模乘法，最後在第 10 章把各層的選擇放在一起比較。
