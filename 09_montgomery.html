第 9 章 · Montgomery Multiplication

Montgomery 乘法

換一個座標系：在「乘上 R」的世界裡，除以 R 只是丟掉低位

成本鏈協定 ECDH→純量乘法 kP→加點／倍點→模乘 mod p→字組乘法

9.1反過來想：消掉低位，而不是估計高位

動機

Barrett 化簡必須估計商：從 $x$ 的高位猜出要減掉幾個 $m$。Montgomery（1985）換了一個方向：不去碰高位，而是加上 $m$ 的適當倍數，讓低位全部變成 0，再整段右移。加上 $m$ 的倍數不改變模 $m$ 的同餘類；右移則等於除以 $R=b^k$，在二進位電腦上不用任何計算。

代價是答案多了一個因子：得到的是 $xR^{-1}\bmod m$，而不是 $x\bmod m$。解法是換一套表示法，讓這個因子自動抵銷。只要整個純量乘法都在這套表示法裡做，進出各換一次的成本，由中間幾千次乘法分攤。

這個方法有兩個前提：$\gcd(m,R)=1$（否則 $R^{-1}$ 不存在），以及輸入 $T<mR$。$R$ 取 2 的冪時，第一個條件就是「$m$ 為奇數」；密碼學用的質數模數當然符合。

三個同名的東西

密碼學裡有三個都叫 Montgomery 的概念，它們是不同的東西：

  • Montgomery 乘法／REDC（本章）：一種模乘的化簡方法，用在任何奇數模數上。
  • Montgomery 階梯（Montgomery ladder，第 5 章）：一種純量乘法的排程，每一位都做一次加點和一次倍點。
  • Montgomery 曲線：形如 $By^2=x^3+Ax^2+x$ 的曲線（例如 Curve25519）。

它們可以一起用，也可以分開用。後兩者關係最近：Montgomery 曲線上的「差分加法」正好配合階梯，只需要 $x$ 座標。

9.2Montgomery 表示：住在「乘上 $R$」的世界

取 $R=b^k>m$（$m$ 有 $k$ 個字組）。對 $x\in\mathbb Z_m$，定義它的 Montgomery 表示

$$\tilde x = xR \bmod m .$$

再定義 $\mathrm{REDC}(T)=TR^{-1}\bmod m$（下一節說明怎麼不用除法算它）。那麼

$$\mathrm{REDC}(\tilde x\,\tilde y) = (xR)(yR)R^{-1} = (xy)R \equiv \widetilde{xy} \pmod m .$$

也就是說，在 $\tilde{\ }$ 的世界裡，「相乘再 REDC」就是乘法。加法和減法本來就相容：$\tilde x+\tilde y=\widetilde{x+y}$。所以整段計算可以全程留在這個世界裡：

步驟計算次數
進入$\tilde x=\mathrm{REDC}(x\cdot (R^2\bmod m))$每個輸入一次
運算$\widetilde{xy}=\mathrm{REDC}(\tilde x\tilde y)$，加減照常幾千次
離開$x=\mathrm{REDC}(\tilde x)$每個輸出一次

$R^2\bmod m$ 只跟模數有關，事先算好一次即可。

9.3REDC：一次消掉一個字組

要算 $TR^{-1}\bmod m$，就要把 $T$ 加上 $m$ 的某個倍數，讓結果被 $R=b^k$ 整除。一次處理一個字組：第 $i$ 輪看目前的數的第 $i$ 個字組 $a_i$（更低的字組前幾輪已經消成 0），想找 $u_i$ 使

$$a_i + u_i m \equiv 0 \pmod b .$$

解是 $u_i = a_i\, m' \bmod b$，其中 $m' = -m^{-1}\bmod b$ 也是預先算好的常數。注意 $u_i$ 只需要模 $b$ 的乘法，也就是一個字組乘一個字組。把 $u_i m b^i$ 加上去，第 $i$ 個字組就變成 0，而且不影響更低的字組（它們已經是 0）。做完 $k$ 輪，低 $k$ 個字組全為 0，右移 $k$ 個字組就是除以 $R$。

手算小例：十進位，$m=4567$，$b=10$，$R=10^4$

$4567\equiv7\pmod{10}$，$7^{-1}\equiv3$，所以 $m'=-3\equiv7\pmod{10}$。對 $T=1234\cdot3211=3962374$：

為什麼最多減一次

加上去的總量是 $Um$，其中 $U=\sum u_ib^i<R$。所以右移後的數是 $(T+Um)/R < (mR + Rm)/R = 2m$。只要再比較一次、必要時減一次 $m$，就落在 $[0,m)$。

Python 參考實作（選讀）：REDC 與交錯式 Montgomery 乘法（HAC 演算法 14.32、14.36）
def mont_setup(m, w):
    """m 必須是奇數；R = b^k > m，m' = -m^(-1) mod b。"""
    k = (m.bit_length() + w - 1) // w
    b = 1 << w
    m_prime = (-inv_euclid(m % b, b)) % b
    return k, m_prime


def redc(T, m, w, k, m_prime):
    """HAC Alg. 14.32：輸入 0 <= T < mR，輸出 T * R^(-1) mod m。
    每一輪把目前最低的字組變成 0，k 輪後整個數右移 k 個字組。"""
    b = 1 << w
    A = T
    for i in range(k):
        a_i = (A >> (w * i)) & (b - 1)
        u_i = a_i * m_prime % b          # 只需要模 b 的乘法
        A += u_i * m << (w * i)          # 這一步讓第 i 個字組歸零
    A >>= w * k                          # 除以 R：只是丟掉低位字組
    return A - m if A >= m else A


def mont_mul(x, y, m, w, k, m_prime):
    """HAC Alg. 14.36：乘法與化簡交錯，x, y < m，回傳 x * y * R^(-1) mod m。"""
    b = 1 << w
    A = 0
    y0 = y & (b - 1)
    for i in range(k):
        x_i = (x >> (w * i)) & (b - 1)
        a0 = A & (b - 1)
        u_i = (a0 + x_i * y0) * m_prime % b
        A = (A + x_i * y + u_i * m) >> w
    return A - m if A >= m else A

上面第二個函式把乘法和化簡交錯進行（HAC 14.36）：每讀 $x$ 的一個字組，就加上 $x_iy$ 再立刻消掉最低字組。中間結果始終小於 $2m$，不必先存整個 $2k$ 字組的乘積。

9.4互動：REDC 逐輪演示

第 $i$ 輪把第 $i$ 個字組消成 0（灰色）；橙色是下一輪要處理的字組。若某個字組本來就是 0，該輪的 $u_i=0$，什麼都不加。最後整段右移。選十進位可以對照上面的手算；選 P-256 或 P-521 則是實際的 64 位元字組。

每一輪只用到 $u_i$ 這一個字組的乘數，算 $u_i$ 只需要一次「字組×字組 mod $b$」。

和 Barrett 不同，這裡完全沒有「估計」：每一輪該加多少是確定的。

9.5互動：進入、相乘、離開，再與 Barrett 對照

REDC 單獨看，答案「不對」：它給的是 $TR^{-1}$。這個元件把完整流程走一遍，並用同一組 $x,y$ 跑 Barrett，確認兩條路得到同一個 $xy\bmod m$。

MONTGOMERY vs BARRETT

9.6成本與取捨

  • 每次乘法的成本和 Barrett 同一個量級（約 $2k^2$ 次字組乘法），但流程完全規則：每一輪做的事一樣，沒有商的估計，進位也只往高位走。這讓它很適合硬體與 SIMD 實作。
  • 適用任何奇數模數：換模數只要換 $m'$ 與 $R^2\bmod m$。許多函式庫用它處理 P-256 的 $p$ 與 $n$，以及 RSA。
  • 需要轉換：只做一兩次乘法時，進出的成本不划算，這時 Barrett 或直接除法比較合適。ECC 的純量乘法有幾千次乘法，轉換成本可以忽略。
  • 最後一次減法與資料有關：和 Barrett 一樣，常數時間的實作會固定做一次條件減法，用遮罩選結果。也有實作省略這次減法，讓輸出留在 $[0,2m)$ 直接進入下一次乘法；但這時兩個輸入的乘積可達 $4m^2$，要保證仍有 $T<mR$，必須取 $R>4m$（例如多留一兩個位元），不能直接拿本章的程式省略減法。
